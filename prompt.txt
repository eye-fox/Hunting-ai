TEMUAN 1: Storage Collision di TVM

Deskripsi

Metode compose() di Storage.java berpotensi menghasilkan kunci penyimpanan yang tidak unik untuk kontrak yang berbeda (storage collision), memungkinkan kontrak A mengakses/menimpa data kontrak B.

Kode yang Dianalisis
RULES(jangan cloning repo(git clone) tapi bawa lewat internet)
File: actuator/src/main/java/org/tron/core/vm/program/Storage.java

```java
private byte[] compose(byte[] key, byte[] addrHash) {
    if (VMConfig.allowTvmCompatibleEvm() && contractVersion == 1) {
        return Hash.sha3(ByteUtil.merge(addrHash, key));
    }
    // ⚠️ FALLBACK: Hanya 16 byte pertama addrHash + 16 byte terakhir key
    byte[] result = new byte[key.length];
    arraycopy(addrHash, 0, result, 0, PREFIX_BYTES);      // 16 bytes
    arraycopy(key, PREFIX_BYTES, result, PREFIX_BYTES, PREFIX_BYTES); // 16 bytes
    return result;
}
```

Poin Validasi (Verifikasi dengan Kode)

# Pertanyaan Perintah Verifikasi
1 Apakah compose() dipanggil di put()/getValue()? grep -n "compose" actuator/src/main/java/org/tron/core/vm/program/Storage.java
2 Apa itu addrHash? Apakah unik per kontrak? grep -n "generateAddrHash" actuator/src/main/java/org/tron/core/vm/program/Storage.java
3 Kapan fallback digunakan? contractVersion berapa? grep -rn "contractVersion" actuator/src/main/java/org/tron/core/vm/ --include="*.java" \| grep -v test
4 Apakah allowTvmCompatibleEvm aktif di mainnet? grep -n "ALLOW_TVM_COMPATIBLE_EVM" chainbase/src/main/java/org/tron/core/store/DynamicPropertiesStore.java
5 Sejarah Git: apakah ini pernah diperbaiki? cd /tmp/opencode/java-tron && git log --oneline -- actuator/src/main/java/org/tron/core/vm/program/Storage.java
6 Apakah ada test yang menangkap ini? find /tmp/opencode/java-tron -name "*Storage*Test.java" \| xargs grep -l "compose\|collision"
7 Apakah ada TIP terkait storage layout? find /tmp/opencode/java-tron -name "*.md" \| xargs grep -i "storage\|compose" 2>/dev/null

TEMUAN 2: Logika suicide/selfdestruct yang Cacat

Deskripsi

Metode suicide2() di Program.java memiliki early-exit ketika owner == obtainer tanpa menjalankan prosedur pembersihan standar (transfer saldo, cancel vote, delete account).

Kode yang Dianalisis

File: actuator/src/main/java/org/tron/core/vm/program/Program.java

```java
public void suicide2(DataWord obtainerAddress) {
    byte[] owner = getContextAddress();
    boolean isNewContract = getContractState().isNewContract(owner);
    if (isNewContract) {
        suicide(obtainerAddress); // jalur aman
        return;
    }
    byte[] obtainer = obtainerAddress.toTronAddress();
    long balance = getContractState().getBalance(owner);
    increaseNonce();

    if (FastByteComparisons.isEqual(owner, obtainer)) {
        return; // ⚠️ EARLY EXIT! Tidak ada pembersihan!
    }
    // transfer balance, vote, freeze...
}
```

Poin Validasi (Verifikasi dengan Kode)

# Pertanyaan Perintah Verifikasi
1 Apakah suicide2() benar-benar ada? grep -n "suicide2" actuator/src/main/java/org/tron/core/vm/program/Program.java
2 Kapan suicide2() dipanggil vs suicide()? grep -rn "suicideAction2\|suicideAction" actuator/src/main/java/org/tron/core/vm/OperationActions.java
3 Apakah allowTvmSelfdestructRestriction() aktif di mainnet? grep -rn "allowTvmSelfdestructRestriction" common/src/main/java/org/tron/core/vm/config/VMConfig.java
4 Apa default value di DynamicPropertiesStore? grep -n "ALLOW_TVM_SELFDESTRUCT_RESTRICTION" chainbase/src/main/java/org/tron/core/store/DynamicPropertiesStore.java
5 Apa impact dari early-exit? Bandingkan suicide() (L451-510) vs suicide2() (L518-544)
6 Apakah ada test untuk skenario owner == obtainer? find /tmp/opencode/java-tron -name "*Selfdestruct*Test.java" -o -name "*Suicide*Test.java"
7 Apakah ada TIP terkait selfdestruct? find /tmp/opencode/java-tron -name "*.md" \| xargs grep -i "selfdestruct\|suicide" 2>/dev/null

PANDUAN VERIFIKASI EKSPERIMENTAL (Opsional)

Jika memungkinkan dan aman (tidak mengganggu mainnet), lakukan verifikasi tambahan:

Untuk Storage Collision:

1. Deploy 2 kontrak dengan trxHash yang prefix-nya sama (birthday attack)
2. Tulis storage di kontrak A di key X
3. Baca storage di kontrak B di key Y yang suffix-nya sama
4. Jika data terbaca → CONFIRMED

Untuk suicide bug:

1. Deploy kontrak yang memanggil selfdestruct(address) dengan address == contract.address
2. Cek saldo kontrak setelah selfdestruct
3. Cek apakah kontrak masih ada di state
4. Jika saldo tetap ada dan kontrak masih ada → CONFIRMED
