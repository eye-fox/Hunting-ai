Anda adalah security researcher. Temukan kerentanan pada repo "https://github.com/Shopify/ucp-proxy". Lakukan analisis mendalam:
update todos lalu jalankan subagent pada tiap phase (1 phase 1 subagent, dan subagent yang dipakai itu sub flow hunter)

PHASE 1: RECONNAISSANCE & PEMAHAMAN REPO
1. **Pahami Repo**:
   - Apa tujuan utama aplikasi ini?
   - Teknologi apa yang digunakan (stack: bahasa, framework, library)?
   - Bagaimana arsitektur aplikasi (client-server, microservices, dll)?
   - Siapa target pengguna dan apa alur bisnis utamanya?
   - Fitur apa yang paling kritis?

2. **Mapping Aplikasi**:
   - Buat daftar semua endpoint/routes yang ditemukan
   - Identifikasi peran setiap file/folder (controller, model, service, middleware, config)
   - Cari file konfigurasi (.env, config.php, settings.py, application.yml)
   - Identifikasi dependency dan versinya (package.json, composer.json, go.mod, requirements.txt)
   
PHASE 2: STATIC CODE ANALYSIS (SCA) MENYELURUH
3. **Lakukan Static Analysis secara sistematis** untuk setiap kategori vulnerability:

 A. **Injection Flaws** (SQLi, NoSQLi, Command Injection, LDAP):
   - Cari pola: query concatenation, exec(), eval(), system(), popen()
   - Periksa semua fungsi database: raw queries, prepared statements, ORM usage
   - Cek input user yang masuk ke shell commands
   - Perhatikan file yang berhubungan dengan database (models, repositories, DAO)

B. **Authentication & Session**:
   - Cek mekanisme login, registrasi, reset password
   - Periksa session management (cookie flags, JWT implementation)
   - Cari hardcoded credentials dalam kode
   - Periksa role/privilege checking di setiap endpoint

C. **Authorization (IDOR/BAC)**:
   - Cek parameter ID (user_id, order_id, document_id) di URL/body
   - Periksa apakah ada validasi kepemilikan resource
   - Cari pola: getById(), findByUserId() tanpa filter ownership

D. **XSS & Output Encoding**:
   - Cari fungsi yang menampilkan user input tanpa escaping
   - Periksa template engine (render, echo, print)
   - Cek penggunaan innerHTML, document.write, eval()
   - Periksa file frontend (JS, Vue, React components)

E. **File Upload & Path Traversal**:
   - Cari fungsi upload file
   - Periksa validasi tipe file, ekstensi, dan content
   - Cek path construction (file_put_contents, move_uploaded_file)
   - Periksa download file dengan parameter path/filename

F. **CSRF & SSRF**:
   - Cek implementasi CSRF token
   - Cari fungsi HTTP request ke external URL (curl, fetch, http.get)
   - Periksa validasi URL yang dimasukkan user

G. **Deserialization & XXE**:
   - Cari unserialize(), pickle.loads(), yaml.load()
   - Periksa XML parsing dengan external entity enabled
   - Cek library yang rentan versi lama

H. **Business Logic**:
   - Identifikasi workflow multi-step
   - Cek validasi status transisi
   - Periksa batasan (rate limiting, quantity limits, discount logic)

I. **Cryptography**:
   - Cek penggunaan hashing (bcrypt vs md5/sha1)
   - Periksa enkripsi data sensitif
   - Cari hardcoded keys/secrets

J. **Error Handling & Information Disclosure**:
   - Cek detail error yang ditampilkan ke user
   - Periksa stack trace, debug mode
   - Cari file .git, .env, backup files
   
PHASE 3: CROSS-FILE CORRELATION
4. **Lakukan penelusuran cross-file untuk setiap temuan**:
Untuk setiap kerentanan potensial yang ditemukan:
   - Telusuri alur data dari input user hingga ke sink (fungsi berbahaya)
   - Periksa file-file terkait: 
     * File yang memanggil fungsi tersebut
     * File yang mendefinisikan class/function tersebut
     * File middleware/validator yang mungkin menjadi filter
     * File konfigurasi yang mungkin mengubah perilaku
     * File patch/update terbaru di commit history
   
   - Cek apakah ada:
     * Sanitization di tempat lain
     * Global input filtering
     * WAF/security layer tambahan
     * Fitur yang sengaja dibiarkan (by design) untuk admin/debug

5. **Periksa commit history**:
   - Cari commit dengan keyword "security", "fix", "vulnerability", "patch"
   - Periksa apakah temuan sudah pernah di-patch
   - Cek apakah patch tersebut masih berlaku untuk kode terbaru
   
PHASE 4: VALIDASI & PROOF OF CONCEPT (PoC)
6. **Validasi dinamis untuk setiap temuan kritis**:

Buat skenario pengujian untuk membuktikan kerentanan:

A. **Untuk Injection**:
   - Siapkan payload untuk menguji injection
   - Coba bypass filter (case, encoding, comment)
   - Uji dengan berbagai input: ' OR 1=1 --, '; exec('id'), dll.

B. **Untuk IDOR**:
   - Buat 2 akun berbeda
   - Coba akses resource akun lain melalui parameter ID
   - Uji dengan parameter terenkripsi/hash

C. **Untuk XSS**:
   - Siapkan payload: <script>alert(1)</script>, <img src=x onerror=alert(1)>
   - Uji berbagai context: HTML, attribute, JavaScript, URL
   - Coba bypass filter dengan encoding, event handler alternatif

D. **Untuk File Upload**:
   - Upload file dengan ekstensi ganda: shell.php.jpg
   - Upload dengan content-type manipulasi
   - Upload file dengan magic bytes
   - Uji path traversal pada filename: ../../../etc/passwd

E. **Untuk SSRF**:
   - Coba akses internal IP: 127.0.0.1, 169.254.169.254
   - Uji dengan URL encoding, DNS rebinding
   - Coba protokol: file://, dict://, gopher://

F. **Untuk Business Logic**:
   - Uji dengan mengubah status parameter
   - Coba replay request multiple times
   - Uji race condition dengan concurrent requests
   - Manipulasi nilai quantity/harga di client-side

7. **Dokumentasi PoC**:
   - Siapkan request/response lengkap (gunakan Burp/curl)
   - Screenshot bukti visual
   - Script automasi untuk replicasi
   - Dampak dan potensi kerugian
   
PHASE 5: FINAL ASSESSMENT
8. **Klasifikasikan temuan akhir**:

Untuk setiap bug yang terkonfirmasi:
   - Beri severity: Critical/High/Medium/Low
   - Jelaskan root cause (kenapa ini terjadi)
   - Beri rekomendasi perbaikan spesifik
   - Tentukan apakah ini by design atau security misconfiguration
   - Tunjukkan apakah ada file lain yang menambal/mitigasi

TOLAK temuan jika:
   - Sudah di-patch di file lain
   - Memerlukan privilege tinggi dan itu by design
   - Hanya terjadi di environment development
   - Hanya bisa diakses oleh admin (by design)
   - Sudah ada CSRF token/Security header yang valid

Hasilkan laporan akhir yang berisi:
   - Ringkasan eksekutif
   - Daftar temuan dengan severity
   - Detail teknis + PoC untuk setiap temuan
   - Rekomendasi perbaikan
   - Kesimpulan tingkat keamanan repo secara keseluruhan
   
INSTRUKSI TAMBAHAN:
1. Gunakan tools: rekomendasikan penggunaan semgrep, gitleaks, trivy, dependency-check untuk scanning otomatis (unduh jika belum terpasang)
2. Perhatikan false positive: jangan lapor jika tidak bisa divalidasi
3. Prioritaskan: fokus ke fitur yang berinteraksi dengan user input
